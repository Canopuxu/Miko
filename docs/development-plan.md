# 开发规划

开发规划作为参考，可依据实际需求、模块适配成本和验证结果调整。每阶段先检查相关已有能力，明确复用范围与必要适配，再实施；界面随功能交付。

| 阶段 | 开发任务 | 验收标准 |
| --- | --- | --- |
| 1. 开发基线 | 独立源码、环境、依赖、配置与数据目录；启动和停止入口 | 可重复启动和停止；运行资料落在 MikoLocal |
| 2. DSH 整合 | 独立 DSH 模型执行；最小统一页面；流式、取消和状态桥接 | 页面能够生成和取消；运行目录与配置独立 |
| 3. 会话保存 | 作者区分、消息与生成状态、SQLite、历史切换和恢复 | 刷新、重启后可续聊；未完成回复有记录 |
| 4. QQ 会话与表达迁移 | 保留两分钟等待、连续聊天与本人接管；适配旧项目的多气泡、引用关系、消息段解析、发送队列和回执恢复；接入可用的表情发送能力 | 能自然分句和接话；引用及混合消息不会一概中断聊天；新消息或本人介入取消旧尾部；不确定发送不会重发 |
| 5. 角色与共同上下文 | 加载审核后的 Miko 设定、你的资料和手动近况；复用角色上下文、相关示例及表情候选组装；保存首次介绍和好友关系；完善相应界面 | Web 与 QQ 使用同一个 Miko；身份自然、介绍不重复；表达参考符合她的设定 |
| 6. 记忆、表达参考与批注 | 确认并接入记忆方案；复用提炼、合并、中文及语义检索；支持人物、类别、日期和来源；按天回顾回复、批注和撤销 | 核心事件跨会话可找回；人物归属准确；修正可追溯，并在相关场景生效 |
| 7. 自主生活 | 保存生活目标与简短每日活动；通过 DSH 更新目标和活动，接入共享记忆与树形轨迹 | 活动跨天延续，目标可改期、搁置和完成，各会话使用一致生活资料 |
| 8. 统一界面完善 | 统一导航、视觉与编辑交互；完善回复回顾、页面关联和集中状态入口 | 现有功能能方便查看管理，草稿与反馈清楚，主要操作流程连贯 |
| 9. 第一版整体验收 | 检查真实聊天、本人接管、记忆修正、生活延续，以及重启、备份和失败恢复 | 完整使用流程成立；关闭页面后后台继续运行；数据可恢复 |

后续规划：电脑截图、浏览历史、前台应用观察，以及浏览器、天气等工具。第一版通过手动近况提供信息，不提前建设电脑采集系统。转达任务不列入需求。
